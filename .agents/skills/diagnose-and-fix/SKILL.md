# 诊断与修复

遵循 `AGENTS.md` 和适用工程约束。诊断本身不授权修改文件。

分别确认：

- 当前可观察行为。
- 预期行为及其权威来源。
- 当前 checkout 上最小且可靠的复现方式。

从可观察入口追踪到负责该行为的规则、adapter 和副作用。区分根因与症状，并确定最小完整修复。

如果任务只要求诊断，在报告证据、原因、影响和推荐方案后停止。

获得修复授权后：

1. 在最近的责任层增加或扩展回归场景。
2. 完成受影响契约和派生产物的修复。
3. 验证原始复现。
4. 根据风险扩大检查范围。

最终报告当前情况与原因、预期情况、解决方案、回归覆盖、实际运行的命令和剩余风险。

不得声称未观察到的修复前或修复后测试结果。
