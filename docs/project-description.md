# StuTrade 项目说明

## 产品定位

StuTrade 是面向校园交易场景的撮合平台。用户可以发布买方需求或卖方供给，系统发现满足双方条件的候选交易；用户也可以直接接受公开需求或供给。平台统一记录挂单、撮合请求、确认结果和履约状态。

第一阶段以二手书交易验证平台能力。普通二手物品、校园跑腿和租赁属于后续产品方向，它们可以复用撮合能力，但领域字段、有效性判断和成交规则仍由各自业务宿主负责。

## MVP 范围

二手书 MVP 包含三条成交路径：

1. **自动撮合**：买方发布 ISBN 和最高价格，卖方发布相同 ISBN 且报价不高于买方预算的书籍；双方确认后按卖方报价成交。
2. **卖方接单**：卖方接受公开的买方需求，按买方报价直接成交。
3. **买方购买**：买方接受公开的卖方供给，按卖方报价直接成交。

成交后，双方可以查看订单并推进最小线下履约状态。MVP 不包含真实支付、聊天、物流、竞价、图片上传和自由文本智能匹配。

## 产品规则

- 金额以分为单位的正整数表示，MVP 固定使用人民币。
- ISBN 作为业务字符串规范化和校验，接受有效 ISBN-10 或 ISBN-13。
- 用户不能与自己发布的需求或供给成交。
- 只有仍然有效且开放的需求和供给可以参与撮合或直接成交。
- 自动撮合以卖方报价成交；卖方接单以买方报价成交；买方购买以卖方报价成交。
- 自动撮合的请求必须由双方确认；重复确认不得重复创建订单。
- 主动接单和主动购买直接完成撮合，不创建对用户可见的虚假反向挂单。
- 同一需求或供给最多建立一笔交易；确认、挂单消耗和订单创建保持原子性。

## 系统形态

平台由业务宿主、通用撮合引擎、前端和 PostgreSQL 组成：

```text
web client --HTTP--> Gin: /api/v1 --> business host --> engine
                                             |
                                             +--> pgx: PostgreSQL
```

- **业务宿主**拥有用户、二手书、订单和履约，执行领域规则并装配进程。
- **撮合引擎**拥有通用 Listing、MatchRequest、价格兼容和状态转换，以同步、确定性的 Go library 运行。
- **前端**独立构建和部署，只通过后端 API 协作；后端不嵌入或提供前端资源。
- **PostgreSQL**是独立数据服务，负责持久化约束、事务和并发正确性。

具体权威来源和跨仓库变更责任见[责任与权威来源](governance/ownership.md)。

## 部署配置

同一个后端命令支持三种部署配置。配置只选择依赖和运行参数，不改变业务规则。

| 配置         | 用途     | 组装结果                                  | PostgreSQL       | Migration      |
| ------------ | -------- | ----------------------------------------- | ---------------- | -------------- |
| `develop`    | 本地开发 | Compose 启动宿主、web HMR 和本地依赖      | Compose 容器     | 启动时执行     |
| `native`     | 本机演示 | Windows 后端 exe 与独立 web 静态产物      | 用户电脑预装     | 后端启动时执行 |
| `production` | 托管部署 | 后端容器、Linux 二进制与独立 web 静态产物 | 服务器或托管服务 | 发布阶段执行   |

命令入口为：

```text
stu-trade.exe
stu-trade serve --profile=develop
stu-trade serve --profile=native
stu-trade serve --profile=production
stu-trade migrate up
stu-trade version
```

`serve` 是默认命令。`native` 在 `127.0.0.1` 提供后端 API，不包含界面，也不要求最终用户安装 Bun、Node.js、Docker 或 C 运行库。`production` 在发布阶段独立执行 migration，再分别部署后端和前端产物。

## 课程交付

课程交付由技术报告、PoC 软件、用户手册、项目展示和小组工作量档案组成。二手书 MVP 的三条端到端路径构成 PoC 与演示的基础；架构边界、状态变化、价格规则和并发场景同时为技术报告、图表和测试评估提供证据。

课程日期、格式和评分要求以 MyAberdeen 与 [`docs/course-requirement-translation/`](course-requirement-translation/) 中的当前材料为准。
